# ③v2 토론 프롬프트 (v0)

공통: 먼저 `phase3/rubric.md`를 읽는다. 호출 시 D(결정월), IN(입력 폴더), OUT(출력 폴더)이 주어진다.
입력은 `IN/D.csv`(후보 전 종목)와 `phase3/inbox/D/`(사용자 제공 리포트, 목록·캡션은 `INDEX.md`. 없으면 건너뜀). 결정일 = CSV의 `as_of`.
파일 읽기·쓰기와 웹검색 외 작업(git, 코드 수정, 셸) 금지.
한국어로 쓴다. 종목마다 5줄 이내.

## [AXIS] 1단계 — 축별 독립 의견 (G / V / M 각각 별도 세션에서 실행)
- 너는 rubric.md 3축 표에서 AXIS 축만 담당한다. 그 축의 CSV 컬럼, inbox 리포트, 웹검색만 사용한다.
- 웹검색은 입력에 없는 사실 확인용이다. 결정일 이전 게시물만, URL과 게시일을 반드시 기록한다.
- 출처 우선순위: 공시(DART·KIND) > 증권사 리포트 > 언론사 기사. 개인 블로그·카페·요약 사이트는 사용 금지.
- 종목 하나를 끝낼 때마다 출력 파일에 바로 추가 저장한다(턴 한도에 걸려도 앞 종목 결과가 남도록).
- 다른 축의 의견 파일(`OUT/work/`)은 읽지 않는다.
- CSV의 모든 종목 각각: 축 점수(0~100, 루브릭 구간 의미 그대로), 근거 최대 3개(출처 포함), 핵심 리스크 1개.
- 출력: `OUT/work/D_AXIS.md` (종목별 `### 티커 종목명` 섹션)

## [SYNTH] 2단계 — 반박 1라운드 + 종합 (별도 세션)
1. `OUT/work/D_G.md`, `D_V.md`, `D_M.md`를 모두 읽는다.
2. 반박: 축 점수 차이가 큰 종목마다, 각 축 의견을 다른 두 축의 근거로 반박하는 문장을 1~2개 쓴다.
   근거 없는 반박은 무효. 반박으로 결론이 바뀌면 이유를 쓴다.
3. 종합: 루브릭 구간 의미로 종목별 최종 점수(0~100)를 정한다. 축 점수의 단순 평균이 아니다.
   출처가 있는 딜 고정·재무위험은 다른 축이 좋아도 0–29.
4. 출력
   - `OUT/D_debate.md`: 축별 요약 → 반박 → 종합 근거 (전문)
   - `OUT/D_scores.csv`: 헤더 `ticker,name,score,g,v,m,reason`
     - ticker는 6자리 문자열(앞자리 0 유지), CSV의 종목 전부, reason은 쉼표 없는 한 문장
- 선정(70점 이상 최대 5개)은 코드가 한다. 점수를 선정 개수에 맞추려 조정하지 말 것.
