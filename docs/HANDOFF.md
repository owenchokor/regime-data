- 재무위험 종목 배제, 피크아웃/랠리 초입 구분은 정량 필터로 먼저 백테스트(사용자 가설 → 9차에서 일부 검증: EPS 상향은 유효, 밸류에이션·업종은 무효로 판명).
- **애널리스트 리포트 자동 수집(신규, 이번 세션 확정, 방식 2 선택)**: 네이버 금융 리서치 등에서 종목별 리포트(날짜·증권사·제목·목표주가·PDF 링크)를 Actions로 자동 수집해 월말 채점표에 붙인다. 과거분까지 모으면 목표가·추정치 변화라는 "기대치" 축의 백테스트 데이터가 되며, 9차에서 가장 크게 비어 있던 축이라 효과가 클 가능성. 착수 전 확인 필요: 네이버·증권사 리서치 페이지의 수집 허용 범위(이용약관), 대안으로 한국투자증권 Open API의 투자의견/목표주가 조회 기능(과거 깊이·앱키 필요, 미확인).

## 리포·브랜치
- `main`: 지금까지 모든 연구(1~9차)·forward(①②+NAV)·문서가 병합 완료. 세션 마지막에 `research/README.md`를 9차 결과로 직접 갱신해 push함(문서 변경은 PR 없이 main 직push 가능함 확인됨 — 브랜치 보호 없음).
- `dart`: **진행 중.** 이전 시도(단일 fnlttMultiAcnt 수집)는 API 응답이 평균 7~10초로 느려 120분 타임아웃으로 실패 → 재설계 후 재수집 중(아래 "DART 재수집" 참고). 완료 후 `main`에 머지 필요.
- 그 외 작업 브랜치(extra-data, nday, forward-nav, us_gate, consolidate)는 전부 main에 머지 완료, 삭제해도 무방.
- 새 수집 워크플로는 `on: push: branches:[<브랜치>] + paths` 방식으로 만든다(workflow_dispatch는 default 브랜치에 파일이 있어야 함). **주의**: 이 방식은 해당 경로 파일을 그 브랜치에 push할 때마다 재실행을 트리거하므로, 수집이 진행 중일 때 같은 파일을 다시 push하면 concurrency group 때문에 대기열에 쌓인다(취소되진 않음, 순서대로 실행). schedule 트리거(forward.yml)는 main에서만 동작.

## DART 재수집 (진행 중, 이 세션에서 재설계)
- 원인: 이전 버전은 중간저장 없이 한 번에 다 받으려다 타임아웃. 새 버전(`collect/fetch_dart.py`, `dart` 브랜치)은:
  - 1) 주요사항보고서 목록(`list.json`, `pblntf_ty=B`, 3개월 창 단위) → `dart_events.parquet` — 주식교환·합병·자산양수도 등 **딜 종목 자동 플래그용**.
  - 2) 다중회사 주요계정(`fnlttMultiAcnt`) — 최근 연도부터 역순, 연도×보고서종류×100개 코드 배치 → `dart_multi.parquet` — 재무위험 필터용.
  - 10분마다 release(`data-latest`)에 중간 저장, 5분마다 `dart` 브랜치에 `PROGRESS_dart.md` 커밋(완료 작업 수·누적 호출·status 분포).
  - 95분 예산 소진 시 `dart_continue` 마커를 남기고 스스로 `gh workflow run fetch-dart.yml --ref dart`로 다음 실행을 자동 호출(체인). `dart_state.json`의 완료 작업 키로 이어받기.
  - API 응답 평균 7.8~10.5초 확인됨 → 전체 완료까지 대략 6~7시간 예상. 이 세션 종료 시점(09:33 UTC) 기준 이벤트 목록 10분 경과 시점.
  - **다음 세션에서 할 일**: `dart` 브랜치의 `PROGRESS_dart.md`로 완료 여부 확인 → 끝났으면 `dart_events.parquet`·`dart_multi.parquet`·`dart_corp.parquet` 다운로드 → 재무위험 필터(자본잠식·연속 영업적자·부채비율)와 딜 배제 규칙을 사전등록해 3차 기준(WF Sharpe ≥ 기준−0.05 등)으로 판정 → `research/variants/README.md`·`research/README.md` 갱신 → `dart` 브랜치를 `main`에 머지.

## 9차 최종 리포트 요약 (자세한 내용은 research/README.md의 "9차"·"최종 결론" 항목)
- 6관점(거시·가치평가·재무·시장분위기·기대치·성장성)을 결정일 기준 정보로 옮겨 74개월×20종목의 월내 IC 계산.
- **EPS 3개월 상향**이 가장 강한 신호(IC +0.123, t 3.4, 전·후반 모두 양). 52주 고점 정확 도달·거래대금 급증·1개월 급등·단기변동성은 일관되게 불리(IC 약 −0.05~−0.08).
- PER·PBR·배당·적자여부·업종·거시레짐은 판별력 없음.
- 표본외 검증(2016–20 규칙 → 2021–26 적용): IC +0.06, 상위5 연 24% vs 후보20 19% vs KOSPI 31%.
- 딜 고정 종목(동양생명·코람코더원리츠 등, proxy 기준 월내 상대수익 −0.8%p)은 정성평가로 배제해야 하는 명확한 유형.
- 결론: 기계 규칙만으론 A안에서 KOSPI를 확실히 이기는 데 필요한 IC 0.15~0.2에 못 미침(표본외 0.06) → 정성평가가 격차를 메워야 함.
- **분석상 주의(중요)**: 첫 시도에서 월별 표가 사후 수익순 정렬이라 동점 처리 시 사후정보가 새어 들어가는 버그가 있었음 → 티커순 재정렬로 수정함(`ic.py`, `oos.py`). 이후 유사 분석 시 항상 동점 순서에 사후정보가 섞이지 않는지 점검할 것.

## 함정 (누적)
- bash 1회 300초 제한 → sleep ≤270초 분할 폴링. 기본 셸 sh → 복잡한 문법은 `bash -c`.
- plotly PNG 저장 불가 → HTML(`include_plotlyjs="cdn"`) 저장.
- `core.LAST_MONTH`(2026-08) 하드코딩 → forward는 자체 월 판정 사용.
- 개별주 월간 패널은 미완성 월 포함 → 수익 정렬 시 `r.index`로 reindex.
- SPA 입력 NaN → 첫 결측월 dropna. 전액 현금 부트스트랩 → nanpercentile.
- 진행 중 Actions 잡 로그는 API로 안 보임(`Host not in allowlist` 등 원인도 로그 없이는 확인 불가) → `PROGRESS_*.md` 커밋 방식으로 진행 확인하는 패턴을 표준으로 삼을 것(이번 세션 DART 재설계에 적용).
- 같은 워크플로 트리거 경로 파일을 수집 진행 중에 다시 push하면 대기열에 중복 실행이 쌓임(취소는 안 됨, concurrency group이 순서대로 처리) — 진행 중엔 해당 파일 재push 자제.
- 사후 정렬된 표에서 동점 처리 시 사후정보 누설 가능 — 순위·IC 계산 전 항상 결정 순서(티커 등)로 재정렬.
